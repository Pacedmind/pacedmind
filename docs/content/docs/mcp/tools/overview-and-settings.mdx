## `get_overview`

**Read-only. Allowed without asking.**

The starting point: today's date and time, the user's preferences, the areas and projects with their ids, the user's team workspaces and what's assigned to the user, the Inbox count, what's overdue, due or planned today, today's calendar, and agent sessions waiting for review or running. Agents call it first to learn the ids, the current date and how the user likes to work.

No parameters.

Returns sections:

* `Now:` the weekday, date, time and ISO week, such as *Now: Thursday 2026-09-24 14:05, week 39*;
* the user's preferences, by topic, under *The user's preferences, for planning and creating tasks (with ids in get_preferences):*. When they'd take more than about 3,000 characters, only their number: *The user's preferences: 42 preferences. Read them with get_preferences before you plan, set dates or create tasks.* Without any: *The user's preferences: none saved yet. When they tell you how they like to work, offer to save it (update_preferences).* See [Preferences](/mcp/tools/preferences);
* **Areas**: name, id, key, color, open tasks and projects, and for a team workspace's area *shared in* and the workspace's name;
* **Team workspaces**, when the user is in one: each with its address, id and the user's role, and how many open tasks there are assigned to the user. See [Team workspaces](/mcp/tools/team-workspaces);
* **Assigned to the user**, when there are such open tasks: up to 20 of them, then *…and 3 more: list_tasks with assignee "me"*;
* **Projects**: name, id, area, open and total tasks, percentage done, target date, color, agent, folder, and which project it starts after;
* **Inbox**: the number of open tasks without an area;
* **Overdue**, **Due today** and **Planned for today**: one line per task;
* **Calendar today**: the day's activities with their event ids;
* **Sessions waiting for the user's review** and **Sessions running**.

Each task line reads: key · status · priority · title · where it lives · due date · planned date · who it's assigned to, when someone is · labels, such as `WRK-31 · In progress · Urgent · Prepare slides for Q4 planning · Q4 planning · due 2026-09-24 17:00 (Thu) · planned 2026-09-24 (Thu) · #presentation`.

## `get_settings`

**Read-only. Allowed without asking.**

The work hours and days the auto-planner uses, how agent sessions start, and the MCP address.

No parameters.

Returns, for example:

```text
Work hours: 09:00–17:00 · Break: 12:30–13:30
Work days: mon, tue, wed, thu, fri
Sessions open in: Windows Terminal · Claude Code command: claude · Codex command: codex
MCP address: http://127.0.0.1:4319/api/mcp
```

On PacedMind Cloud's server, where sessions start is each computer's own setting, so it says:

```text
Work hours: 09:00–17:00 · Break: 12:30–13:30
Work days: mon, tue, wed, thu, fri
Sessions start on the user's computers, as each computer's PacedMind desktop app says.
MCP address: https://app.pacedmind.com/api/mcp
```

## `update_settings`

**Changes data.**

Changes the work hours, break and work days that the auto-planner fills with focus blocks. Parameters left out keep their value.

| Parameter | Type | Description |
| --- | --- | --- |
| `work_start` | string | Start of the work hours, `HH:mm`. |
| `work_end` | string | End of the work hours, `HH:mm`. |
| `break_start` | string | Start of the daily break, `HH:mm`. |
| `break_end` | string | End of the daily break, `HH:mm`. |
| `work_days` | string list | Days such as `["mon", "tue", "wed", "thu", "fri"]`. |

Returns the new values: *Work hours 09:00–17:00, break 12:30–13:30, work days mon, tue, wed, thu, fri.*

Errors: *Work has to start before it ends.*, *The break has to start before it ends.*, *work_start needs a time like 09:00.*, and *Unknown day "…". Use mon, tue, wed, thu, fri, sat or sun.*

The terminal and the agent commands can only be changed in **Settings → Sessions**. See [Work hours and days](/planning/work-hours).
